# Installation: dependencies and configuration

Covers both plans. `stack.py install` will automate every step below and stop with a clear message when one fails.
It asks before installing system components. This page is also the manual path.

Runtimes (`runtime:` in `machines/<host>.yaml`):
- `native` (default): no Docker. Services run as native processes under `stack.py up` and the tray. This is how
  SEKAIHOME runs today.
- `compose`: a Docker Compose file generated by `stack.py build`. Default on the Plan A cloud VM and other Linux
  servers.
- `harbor` (optional): Harbor runs Open WebUI and LiteLLM. Not installed on SEKAIHOME (decided 2026-10-26: WSL2 and
  Docker were not installed; see section 4 for what is still unverified).

## 1. What runs where

| Piece | Plan B, `native` (SEKAIHOME) | Plan A VM, `compose` |
|---|---|---|
| Ollama | native app (GPU, mmap tuning) | none on the VM; private hosts run it |
| LiteLLM + privacy hook | uv tool `litellm[proxy]` with `--with-editable packages/privacy-gate` | container |
| Open WebUI | uv tool `open-webui` | container |
| privacy-gate (+ MCP) | `uv run` service in the project environment | container |
| Postgres | native install | container |
| Identity (Authelia, LLDAP, invites) | SEKAIHOME (`edge` mode; native builds confirmed in B-S0) | containers inside the confidential main VM |
| Key broker (OpenBao) | not needed | on owned hardware (SEKAIHOME or the admin's machine) |
| ffmpeg (video frames) | native binary on PATH | inside the gate image |
| Detector models (ONNX) | downloaded by privacy-gate on first start into `.run/models/` | baked into the gate image |

### 2.2 Linux server or cloud VM, `compose` runtime (Plan A)

| # | Dependency | Install |
|---|---|---|
| 1 | Docker Engine + compose plugin | Docker's apt repository: `docker-ce docker-ce-cli containerd.io docker-compose-plugin` |
| 2 | NVIDIA driver + NVIDIA Container Toolkit | only on a GPU host (not the Plan A main VM) |
| 3 | git, curl, uv | `apt install git curl`; `curl -LsSf https://astral.sh/uv/install.sh \| sh` |
| 4 | WireGuard | `apt install wireguard` (Plan A `onprem` link and broker, Plan B edge relay) |
| 5 | cryptsetup, restic | `apt install cryptsetup restic` (Plan A: LUKS data disk, client-side encrypted backups) |
| 6 | Attestation tools | chosen in A-S0 for the machine type (SEV-SNP or TDX guest tools) |
| 7 | OpenBao (key broker) | on owned hardware, not on the VM: OpenBao release binary for that OS |

Plan A uses Confidential VM machine types only (N2D with SEV-SNP for the main VM; C3 with TDX or A3 with H100
confidential computing for model servers). On the VMs all of this runs from the Terraform startup script. The admin
runs the installer from their own machine (gcloud + Terraform), not from Cloud Shell, so key material never passes
through a Google-hosted shell.

## 3. Configuration steps

1. **Machine profile:** `uv run scripts/stack.py doctor --write-profile` (picks models from the hardware; sets
   `runtime`, default `native` on Windows).
2. **Dependencies and secrets:** `uv run scripts/stack.py setup` installs what section 2 lists (asking first for
   system components), writes `.env` and pulls the core models.
3. **Generate configs:** `uv run scripts/stack.py build` writes the LiteLLM config with `privacy_hook`, the gate
   config, the Open WebUI models, filter and tool-server entry, the Claude Code profile B environment (private
   aliases only, non-essential traffic off, web tools denied), and for `compose` the compose file. External aliases
   appear only when `external.enabled` is true in `policy/privacy.yaml`.
4. **Start:** `native`: `uv run scripts/stack.py up` (or let the tray start everything). `compose`:
   `docker compose -f infrastructure/compose/<deployment>.yaml up -d`.
5. **Provision Open WebUI:** `uv run scripts/stack.py webui-provision` creates the admin (or relies on OIDC) and
   imports department models, the filter function and the privacy-gate tool server through Open WebUI's API.
6. **Verify:** `uv run scripts/stack.py smoke` and `uv run scripts/stack.py gate-eval` must both pass.
7. **Other clients** (optional): OpenCode and Continue use the generated configs, whose only model endpoint is
   LiteLLM, and list the privacy-gate MCP server. Claude Code profile B is for the owner's development work. No
   integration is provided for Claude Code profile A, Claude Desktop or other apps that talk to their own cloud: they
   are outside the privacy boundary.
8. **External models** (optional, off by default): set `external.enabled: true` and the providers in
   `policy/privacy.yaml`, add their keys, rebuild, then grant the `external` group to chosen users in the admin UI.
   Each user still opts in and confirms per conversation.
9. **Multi-user (Plan A, or Plan B `edge`):** start the identity services (Plan A: in the main VM; Plan B: on
   SEKAIHOME, plus the edge relay through `stack.py install --edge gcp`), create the first admin, enroll TOTP and a
   passkey on first sign-in.

Updating: `git pull`, `stack.py setup` (upgrades pinned tools), `stack.py build`, then restart (`stack.py down` /
`up`, or `docker compose ... up -d`). Removing: `stack.py down`, `stack.py tray --remove-startup`,
`uv tool uninstall litellm open-webui`, then Ollama and PostgreSQL from Apps.

## 4. Optional: `harbor` runtime

Harbor (https://github.com/av/harbor) runs Open WebUI and LiteLLM in Docker. Choose it on a Linux machine that already
runs Docker, or on Windows if WSL2 and Docker are acceptable there.

Extra dependencies:

| Platform | Dependencies |
|---|---|
| Windows | WSL2 + Ubuntu 24.04 (`wsl --install -d Ubuntu-24.04`, admin prompt and one reboot; `--location` to put the disk on another drive), `.wslconfig` with `memory=6GB`, `swap=2GB`, `processors=4`, `networkingMode=mirrored`; `/etc/wsl.conf` with `systemd=true`; Docker Engine inside WSL (preferred over Docker Desktop: open source, less overhead, no licence question); git, curl, uv inside WSL |
| Linux | Docker Engine; NVIDIA Container Toolkit if Harbor runs Ollama in a container |

Configuration outline: install Harbor per its README; set `ollama.internal_url` to the native Ollama
(`harbor config set ollama.internal_url http://<host>:11434`; on Windows Ollama must listen on `0.0.0.0` with a
firewall rule limited to the WSL network); set Harbor's default services to `webui litellm`; point Harbor's LiteLLM
at `infrastructure/litellm/config.yaml` and mount the hook and gate package; run our gate and Postgres as a Compose
project on Harbor's network; `harbor up`; then steps 5-9 above.

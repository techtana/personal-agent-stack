# Installation: dependencies and configuration

Covers both plans. `stack.py install` will automate every step below and stop with a clear message when one fails.
It asks before installing system components. This page is also the manual path.

Runtimes (`runtime:` in `machines/<host>.yaml`):
- `native` (default): no Docker. Services run as native processes under `stack.py up` and the tray. This is how
  SEKAIHOME runs today.
- `compose`: a Docker Compose file generated by `stack.py build`. Default on the Plan A cloud VM and other Linux
  servers.
- `harbor` (optional): Harbor runs Open WebUI and LiteLLM. Not installed on SEKAIHOME (decided 2026-10-26: WSL2 and
  Docker were not installed; see section 4 for what is still unverified).

## 1. What runs where

| Piece | Plan B, `native` (SEKAIHOME) | Plan A VM, `compose` |
|---|---|---|
| Ollama | native app (GPU, mmap tuning) | none on the VM; private hosts run it |
| LiteLLM + privacy guardrail | uv tool `litellm[proxy]` with `--with-editable packages/privacy-gate` | container |
| Open WebUI | uv tool `open-webui` | container |
| privacy-gate (Presidio, detect-secrets, deface, topic model) | `uv run` service in the project environment | container |
| Postgres | native install | container |
| Identity | Keycloak on SEKAIHOME (`edge` mode; confirmed in B-S0) | Authentik containers inside the confidential main VM |
| Key broker (Trustee) | not needed | on owned hardware (SEKAIHOME or the admin's machine) |
| ffmpeg, Tesseract, metadata tool | native (ExifTool on Windows) | inside the gate image (mat2 on Linux) |
| Detector models (ONNX) | downloaded by privacy-gate on first start into `.run/models/` | baked into the gate image |

## 2. Dependencies

### 2.1 Windows, `native` runtime (Plan B)

System packages are declared in one WinGet Configuration file, `winget/configuration.winget` (generated by
`stack.py build`), and installed with the tool built into Windows 11:

```powershell
winget configure --enable    # once per machine; turns on winget's configuration feature
winget configure --file winget\configuration.winget --accept-configuration-agreements
```

`edge` mode uses `winget\configuration.edge.winget`, which adds OpenJDK and Caddy.

| # | Dependency | Source | Configure |
|---|---|---|---|
| 1 | NVIDIA driver | already installed (610.88) | - |
| 2 | uv, git | winget configuration (`astral-sh.uv`, `Git.Git`) | - |
| 3 | Ollama | winget configuration (`Ollama.Ollama`) | `stack.py doctor --write-profile` picks models; `stack.py setup` writes the Ollama user env and restarts the app |
| 4 | PostgreSQL 17 | winget configuration (`PostgreSQL.PostgreSQL.17`) | `stack.py setup` creates databases `litellm` and `gate` with their own roles, writes `DATABASE_URL`, `GATE_DATABASE_URL`; `shared_buffers=128MB` |
| 5 | ffmpeg | winget configuration (`Gyan.FFmpeg`) | on PATH for video frames |
| 6 | Tesseract OCR | winget configuration (`UB-Mannheim.TesseractOCR`) | OCR engine for Presidio Image Redactor; language packs per G1 |
| 7 | ExifTool, qpdf | winget configuration (`OliverBetz.ExifTool`, qpdf) | metadata stripping on Windows, where mat2 does not run natively: ExifTool for images, video and PDF, `qpdf --linearize` to drop old PDF revisions; Office and audio files are cleaned by the gate's own code or refused (V11) |
| 8 | OpenJDK (`edge` mode only) | winget configuration (the version the pinned Keycloak release requires; OpenJDK 25 for 26.8) | for Keycloak |
| 9 | Keycloak (`edge` mode only) | release archive from keycloak.org, checksum verified by `stack.py setup` | at least 26.7.3 (CVE-2026-16072); registered as a Windows service with `kc.bat tools windows-service install` (V7); realm imported from `infrastructure/identity/keycloak-realm.json` |
| 10 | Python 3.11 / 3.12 | fetched by uv | - |
| 11 | LiteLLM, Open WebUI | `uv tool install` by setup (pinned); LiteLLM `--with-editable packages/privacy-gate` | started through each environment's python.exe (Smart App Control) |
| 12 | Presidio, detect-secrets, deface, fastembed | dependencies of `packages/privacy-gate`, installed by uv; models downloaded on first start into `.run/models/` | spaCy or transformers NER model per G1/G2 |
| 13 | Claude Code (optional, owner development only) | `Anthropic.ClaudeCode` | use profile B (`scripts/claude-local.ps1`) for anything private; profile A and Claude Desktop are outside the privacy boundary and get no integration |
| 14 | Start automatically | - | `owner` mode: the tray's Startup shortcut starts every native service at sign-in. `edge` mode: `stack.py tasks install` (elevated shell) registers one Task Scheduler "at startup" task per service under `\AgentStack\`; each runs `stack.py run <svc>`, which restarts the service with backoff, and a 2-minute repeating trigger restarts the supervisor if it dies (Task Scheduler's own restart on failure does not, V10). `up`, `down` and the tray leave task-supervised services alone; the tray becomes a status viewer |

Whether every package installs unattended and whether Smart App Control allows each binary is item V9.

### 2.2 Linux server or cloud VM, `compose` runtime (Plan A)

| 5 | cryptsetup, restic | `apt install cryptsetup restic` (Plan A: LUKS data disk, client-side encrypted backups) |

Plan A uses Confidential VM machine types only (N2D with SEV-SNP for the main VM; C3 with TDX or A3 with H100
confidential computing for model servers). On the VMs all of this comes from cloud-init in the Terraform templates. The admin
runs the installer from their own machine (gcloud + Terraform), not from Cloud Shell, so key material never passes
through a Google-hosted shell.

## 3. Configuration steps

1. **Machine profile:** `uv run scripts/stack.py doctor --write-profile` (picks models from the hardware; sets
   `runtime`, default `native` on Windows).
2. **Dependencies:** Windows: `winget configure --file winget\configuration.winget` (section 2.1). Linux: cloud-init
   or the same apt list by hand.
3. **Secrets, databases, models:** `uv run scripts/stack.py setup` writes `.env`, creates the PostgreSQL databases,
   installs the pinned uv tools and pulls the core models.
4. **Generate configs:** `uv run scripts/stack.py build` writes the LiteLLM config with the privacy guardrail, the
   `external` access group and request logging without prompts, the gate config, the Open WebUI models and filter, the Claude Code profile B environment (private
   aliases only, non-essential traffic off, web tools denied), and for `compose` the compose file. External aliases
   appear only when `external.enabled` is true in `policy/privacy.yaml`.
5. **Start:** `native`: `uv run scripts/stack.py up` (or let the tray start everything). `compose`:
   `docker compose -f infrastructure/compose/<deployment>.yaml up -d`.
6. **Provision Open WebUI:** `uv run scripts/stack.py webui-provision` creates the admin (or relies on OIDC), the
   `external` group, the department models and the filter function through Open WebUI's API.
7. **Verify:** `uv run scripts/stack.py smoke` and `uv run scripts/stack.py gate-eval` must both pass.
8. **Other clients** (optional): OpenCode and Continue use the generated configs, whose only model endpoint is
   LiteLLM. Claude Code profile B is for the owner's development work. No
   integration is provided for Claude Code profile A, Claude Desktop or other apps that talk to their own cloud: they
   are outside the privacy boundary.
9. **External models** (optional, off by default): set `external.enabled: true` and the providers in
   `policy/privacy.yaml`, add their keys, rebuild, then add chosen users to the `external` group (identity provider
   -> Open WebUI group -> LiteLLM team).
   Each user still opts in and confirms per conversation.
10. **Multi-user (Plan A, or Plan B `edge`):** start the identity provider (Plan A: Authentik in the main VM; Plan B:
    Keycloak on SEKAIHOME, plus the edge relay through `stack.py install --edge gcp`), import the generated realm or
    flows, create the first admin, enroll TOTP and a passkey on first sign-in.

Updating: `git pull`, `stack.py setup` (upgrades pinned tools), `stack.py build`, then restart (`stack.py down` /
`up`, or `docker compose ... up -d`). Removing: `stack.py down`, `stack.py tray --remove-startup`,
`uv tool uninstall litellm open-webui`, then Ollama and PostgreSQL from Apps.

## 4. Optional: `harbor` runtime

Harbor (https://github.com/av/harbor) runs Open WebUI and LiteLLM in Docker. Choose it on a Linux machine that already
runs Docker, or on Windows if WSL2 and Docker are acceptable there.

Extra dependencies:

| Platform | Dependencies |
|---|---|
| Windows | WSL2 + Ubuntu 24.04 (`wsl --install -d Ubuntu-24.04`, admin prompt and one reboot; `--location` to put the disk on another drive), `.wslconfig` with `memory=6GB`, `swap=2GB`, `processors=4`, `networkingMode=mirrored`; `/etc/wsl.conf` with `systemd=true`; Docker Engine inside WSL (preferred over Docker Desktop: open source, less overhead, no licence question); git, curl, uv inside WSL |
| Linux | Docker Engine; NVIDIA Container Toolkit if Harbor runs Ollama in a container |

Configuration outline: install Harbor per its README; set `ollama.internal_url` to the native Ollama
(`harbor config set ollama.internal_url http://<host>:11434`; on Windows Ollama must listen on `0.0.0.0` with a
firewall rule limited to the WSL network); set Harbor's default services to `webui litellm`; point Harbor's LiteLLM
at `infrastructure/litellm/config.yaml` and mount the hook and gate package; run our gate and Postgres as a Compose
project on Harbor's network; `harbor up`; then steps 6-10 above.

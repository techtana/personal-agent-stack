# Installation: dependencies and configuration (Harbor-based)

Covers both plans. `stack.py install` will automate every step below and stop with a clear message when one fails.
It asks before installing system components (WSL, Docker, drivers). This page is also the manual path.

Lines marked **(H0)** depend on Harbor details to confirm in the first work package (a half-day spike on SEKAIHOME):
exact install command, the config key for LiteLLM's config file, the Docker network name, and how containers reach a
native Ollama from WSL2. Harbor docs: https://github.com/av/harbor

## 1. What gets installed where

| Piece | Plan B on Windows (SEKAIHOME) | Plan A cloud VM / any Linux server |
|---|---|---|
| GPU driver | NVIDIA driver on Windows (already installed) | NVIDIA driver + NVIDIA Container Toolkit, only on a GPU host |
| Ollama | native Windows app (keeps the GPU and mmap tuning) | none on the VM; private hosts run it (Plan A) |
| Linux environment | WSL2 with Ubuntu 24.04 | the VM's Debian/Ubuntu |
| Container engine | Docker Engine inside WSL2 (recommended) or Docker Desktop | Docker Engine |
| Harbor | inside WSL2 | on the VM |
| Open WebUI, LiteLLM | Harbor services | Harbor services |
| privacy-gate, Postgres | our Compose project `infrastructure/gate/`, on Harbor's network | same |
| Identity edge (multi-user) | edge VM (Plan B `edge` mode) | on the VM |
| uv, git | inside WSL2 (and on Windows for Claude Code hooks) | on the VM |
| ffmpeg, ONNX models | inside the gate image; nothing on the host | same |

## 2. Dependencies

### 2.1 Windows (Plan B)

| # | Dependency | Install | Configure |
|---|---|---|---|
| 1 | NVIDIA driver | already installed (driver 610.88) | - |
| 2 | Ollama | `winget install --id Ollama.Ollama --exact` | `uv run scripts/stack.py doctor --write-profile` writes the model lineup; the installer sets the Ollama user env from it (as today) and adds `OLLAMA_HOST=0.0.0.0:11434` so WSL can reach it; a Windows Firewall rule allows 11434 only from the WSL network |
| 3 | WSL2 + Ubuntu | `wsl --install -d Ubuntu-24.04` (reboot once) | `%UserProfile%\.wslconfig`: `[wsl2]` `memory=6GB`, `swap=2GB`, `processors=4`, `networkingMode=mirrored` (H0: confirm containers reach Windows Ollama this way; fallback is the Windows host IP from `ip route` in WSL) |
| 4 | systemd in WSL | - | `/etc/wsl.conf`: `[boot]` `systemd=true`, then `wsl --shutdown` |
| 5 | Docker Engine (in WSL) | Docker's apt repository: `docker-ce docker-ce-cli containerd.io docker-compose-plugin` | `sudo usermod -aG docker $USER`; `sudo systemctl enable --now docker` |
| 6 | git, curl | `sudo apt install -y git curl` | - |
| 7 | uv | `curl -LsSf https://astral.sh/uv/install.sh \| sh` | - |
| 8 | Harbor | per Harbor README, for example `git clone https://github.com/av/harbor.git ~/harbor && ~/harbor/harbor.sh ln` (H0) | section 3 |
| 9 | Start at sign-in | - | a Task Scheduler entry runs `wsl -d Ubuntu-24.04 -u <user> -- harbor up` at logon; Docker restart policies keep containers up |

Docker Desktop instead of 4-5 is possible, but it adds its own VM overhead, and its licence requires a paid
subscription for larger organisations. Docker Engine inside WSL is open source.

RAM: the WSL VM is capped at 6 GB (Open WebUI ~1 GB, LiteLLM ~0.6 GB, privacy-gate ~0.9 GB, Postgres ~0.2 GB, plus
headroom). With qwen3.5:9b as the primary, SEKAIHOME has ~17 GB available while the model is loaded
(`memory/state.md`), so this fits. The 35B MoE primary does not leave room for it.

### 2.2 Linux server or cloud VM (Plan A)

| # | Dependency | Install |
|---|---|---|

| 2 | NVIDIA driver + NVIDIA Container Toolkit | only on a GPU host (Plan A private host on a VM; not needed on the main VM) |

## 3. Configuration steps

Run inside WSL (Plan B) or on the VM (Plan A), from the repo checkout. On Windows the checkout can stay at
`C:\Code\personal-agent-stack` and be used from WSL as `/mnt/c/Code/personal-agent-stack`.

1. **Machine profile:** `uv run scripts/stack.py doctor --write-profile` (unchanged; picks models from the hardware).
2. **Secrets:** `uv run scripts/stack.py install --secrets-only` writes `.env` with generated values; add provider
   keys.
3. **Generate configs:** `uv run scripts/stack.py build` writes the LiteLLM config with `privacy_hook`, the gate
   config, the Open WebUI models, filter and tool-server entries, the skill copies, `.mcp.json` and Claude Code hooks.
4. **Point Harbor at native Ollama (Plan B):** `harbor config set ollama.internal_url http://<windows-host>:11434`
   (H0 decides `<windows-host>`), and leave Harbor's own `ollama` service out of the defaults.
5. **Choose Harbor services:** `harbor defaults` set to `webui litellm` (H0: exact command).
6. **Give LiteLLM our config and hook:** point Harbor's LiteLLM config at `infrastructure/litellm/config.yaml` and
   mount `privacy_hook.py` and the `privacy-gate` package (H0: the config key or override file Harbor uses).
7. **Open WebUI environment:** `harbor env webui` entries from the build output: LiteLLM as the only OpenAI
   connection, direct connections off, task model `webui-task`, RAG embeddings `private-embed`, web search off,
   forwarded user headers on; OIDC settings in multi-user mode.
8. **Start our services:** `docker compose -f infrastructure/gate/compose.yaml up -d` (privacy-gate, Postgres),
   attached to Harbor's network (H0: network name).
9. **Start Harbor:** `harbor up`.
10. **Provision Open WebUI:** `uv run scripts/stack.py webui-provision` creates the admin (or relies on OIDC), imports
    department models, the filter function and the privacy-gate tool server through Open WebUI's API.
11. **Verify:** `uv run scripts/stack.py smoke` and `uv run scripts/stack.py gate-eval` must both pass.
12. **Connect other apps** (optional):
    - Claude Code: the generated `.mcp.json` entry `privacy-gate` and hooks load when you open the repo; approve the
      server once.
    - Claude Desktop and other stdio clients: add `{"command": "uv", "args": ["run", "--project", "<repo>",
      "privacy-gate", "mcp", "--stdio"]}` to the app's MCP config.
    - OpenCode, Continue: the generated configs point at LiteLLM (enforced) and list the MCP server.
13. **Multi-user (Plan A, or Plan B `edge`):** deploy `infrastructure/edge/` (Plan B: on the edge VM by
    `stack.py install --edge gcp`), create the first admin, and enroll TOTP and a passkey on first sign-in.

## 4. Updating and removing

| Task | Command |
|---|---|
| Update Harbor services | `harbor pull` then `harbor up` (H0) |
| Update this repo's parts | `git pull`, `stack.py build`, `docker compose -f infrastructure/gate/compose.yaml up -d --build` |
| Stop everything | `harbor down` and `docker compose -f infrastructure/gate/compose.yaml down` |
| Remove | the above, then remove Harbor's directory, `wsl --unregister Ubuntu-24.04` (Plan B; deletes the WSL disk), Ollama from Apps |

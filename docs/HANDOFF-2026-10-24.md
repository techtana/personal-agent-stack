## 1. Owner's goals (authoritative)

A professional local coding-agent stack with department agents (app-dev, testing, security, devops,
code-review, docs) that:

1. uses the right tool for the right bandwidth tier (tiny local for autocomplete, local for cheap/simple,
   cloud for heavy);
2. is **self-developing** (improves its own prompts/routing/skills from experience, human-approved);
3. minimises cost;
4. is **intuitive** to interact with, composed from multiple open-source tools rather than one custom monolith.

Hardware/software: Windows 11, RTX 3060 12 GB, system RAM unknown (ask: 16/32/64 GB — it decides the model
tier), Docker Desktop (WSL2), **Ollama already installed natively**, Open WebUI already running, VS Code,
Claude Code. Billing mode for Claude Code unknown (ask: Max/Pro subscription vs API key — it decides topology).

### 4.2 Bandwidth tiers (signals that move a task between tiers)

| Tier | Runs on | Used for | Moves up when |
|---|---|---|---|
| T0 autocomplete | Ollama `qwen2.5-coder:1.5b-base` (~1 GB, always resident) | FIM in editor | never |
| T1 local chat/edit | Ollama small dense (qwen3.5:9b / qwen3:14b @16k) **or** llama-server MoE | one-shot edits, docs drafts, commit msgs, log triage, summaries | context near `num_ctx`, malformed tool calls >=2, user says "escalate" |
| T2 local agentic | same weights, thinking on, 32-64k ctx (MoE only) | multi-step local tasks, first-pass review | stall (same tool call repeated), >N turns, test loop fails twice |
| T3 cloud agentic | `claude-sonnet-5-5` (effort low/medium for routine) | multi-file refactors, planning, review verdicts | security/architecture tags |
| T4 cloud heavy | `claude-opus-5-5` (security/code-review deep mode); `claude-fable-5-1` only on explicit request | threat models, architecture sign-off | — |
| cheap cloud | `claude-haiku-5-5` ($0.10/$0.50) — often beats a 7B local on quality for near-zero cost | classification, judge, titles/summaries, nightly reflection | — |

Cost rule of thumb from the research: route **local** for privacy/offline/rate-limit reasons and for T0;
otherwise Haiku 5.5 is so cheap that "local to save money" only pays off for the big MoE tier.
Measure "cost per accepted answer" per department, not per request.

### 4.4 Claude Code specifics (verified from code.claude.com / ollama repo unless marked)

- Ollama has served Anthropic `/v1/messages` since v0.14.0 (Jan 2026):
  `ANTHROPIC_BASE_URL=http://localhost:11434 ANTHROPIC_AUTH_TOKEN=ollama ANTHROPIC_API_KEY=""` or
  `ollama launch claude --model <m>`. Tools/streaming/thinking work; `tool_choice`, `count_tokens`,
  prompt caching do not.
- One `ANTHROPIC_BASE_URL` per Claude Code process. Subagent `model:` accepts any string `--model` accepts,
  so per-department local/cloud mixing needs the gateway to map model names (or the
  `x-claude-code-request-class` / `x-claude-code-agent-type` hint headers, `CLAUDE_CODE_GATEWAY_HINT_HEADERS=1`).
  **Unverified:** whether a non-`claude-*` string in subagent frontmatter passes through verbatim — test with
  `claude --debug` (2 minutes).
- Any gateway credential replaces Max-subscription billing with per-token billing. Hence two profiles:
  (A) `claude` direct to Anthropic on the subscription for heavy work; (B) `CLAUDE_CONFIG_DIR=~/.claude-local`
  alias `claude-local` pointed at Ollama or LiteLLM for local/mixed sessions. Set
  `CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS=1` on the local profile; set `CLAUDE_CODE_MAX_CONTEXT_TOKENS`,
  `CLAUDE_CODE_MAX_OUTPUT_TOKENS`, `CLAUDE_CODE_AUTO_COMPACT_WINDOW` to the local `num_ctx`.
- `ANTHROPIC_SMALL_FAST_MODEL` is deprecated → `ANTHROPIC_DEFAULT_HAIKU_MODEL`; also `CLAUDE_CODE_SUBAGENT_MODEL`.
- Native primitives to use instead of the old FSM: `.claude/agents/*.md` (model/tools/permissionMode/memory/
  maxTurns/hooks), `.claude/skills/*/SKILL.md` (`context: fork`), hooks (Stop/SubagentStop/SessionStart/
  TaskCompleted/PostToolUse), `.mcp.json`, OTel (`CLAUDE_CODE_ENABLE_TELEMETRY=1`), `--agent`.
- Model ID note: Claude Code docs resolve `haiku` → `claude-haiku-5-5` (v2.1.293+); this sandbox's runtime
  listed `claude-haiku-4-5-20251001`. Resolve with `GET /v1/models` using the owner's key before pinning.

### 4.5 Gateway: LiteLLM (verified in source at v1.108.0, 2026-10-24)

- `ollama_chat/` supports tools + `num_ctx`; `ollama/` does **not** accept tools — use `ollama_chat/`.
- Native `/v1/messages` + `/v1/messages/count_tokens` bridge any deployment with tools preserved.
- First-class `auto_router/complexity_router` deployment type: tier ladders, rule-based classifier (<1 ms),
  optional local-LLM classifier, `plan_mode_min_tier`, `enable_context_window_escalation`,
  `stall_escalation_enabled` (bumps tier when a weak model loops), session affinity; `adaptive_router`
  (Thompson sampling, needs Postgres) for the self-developing requirement; routing decisions logged.
- `CustomLogger.async_pre_call_hook` can rewrite the model if custom logic is needed.
- **Verify before adopting:** exact image tag convention on the GitHub releases page; license text; an alleged
  supply-chain incident around 1.82.7/1.82.8 (pin a verified version); smoke-test a Read/Edit tool round-trip
  Claude Code → LiteLLM `/v1/messages` → `ollama_chat` (issue #24091 reported dropped tool calls on 1.82.4).
- Strip `temperature/top_p/top_k`, forced `tool_choice`, `thinking: disabled` for Anthropic 5.x
  (`drop_params`); set `output_config.effort` low/medium per cloud tier for routine work; forward
  `cache_control`/system array unchanged.

### 4.7 Self-development loop (human-gated, never auto-merge)

1. Capture (all local): LiteLLM spend + routing-decision logs; Claude Code hooks (`Stop`, `SubagentStop`,
   `PostToolUse` on test commands) → `traces/*.jsonl` {agent, model, tokens, duration, tool calls,
   test pass/fail, escalation}; Open WebUI thumbs export nightly.
2. Nightly retrospective (`scripts/retro.py`, Task Scheduler/cron, or `/retro` skill): local model clusters
   failures → Haiku 5.5 (hard token cap) proposes **<=3 deltas** to allowlisted paths
   (`skills/*/SKILL.md`, `agents/*.yaml`, `infrastructure/litellm/config.yaml` tier boundaries).
3. Eval gate: `evals/<dept>/promptfooconfig.yaml` (15-30 golden prompts from past thumbs/test cases, run 3x,
   no regression allowed) + skill-creator's eval loop for SKILL.md changes.
4. PR opened with evidence; owner approves in the morning; merge triggers the generator.
5. Promotion/demotion rule for local models encoded in config, edited only via PR.
Patterns referenced: Kiro kiro-trace, OpenAI Agent Improvement Loop cookbook (May 2026), ACE delta updates,
GEPA (revisit after 4-6 weeks of traces), Karpathy autoresearch.

### 4.8 Observability (lightest viable)

LiteLLM Postgres spend logs + `/metrics` → Prometheus/Grafana (reuse Anthropic's claude-code-monitoring
compose: otel-collector-contrib + Prometheus + Grafana); LiteLLM OTel callback → **Arize Phoenix**
(single container, SQLite, ports 6006/4317, ~1-2 GB); `nvidia_gpu_exporter` as a native Windows service
(:9835) for GPU temp/VRAM — replaces the pynvml sidecar; Claude Code OTel on. **Skip** Langfuse v4 (6 containers,
~16 GiB), Opik, Helicone (ClickHouse). Per-department LiteLLM virtual keys with `max_budget` are the hard cost
stop that replaces DESIGN.md's 20-calls/session cap.

### 4.9 MCP (spec 2026-07-28 — stateless, Mcp-Method/Mcp-Name headers mandatory; SDKs: python mcp 2.3.0,
fastmcp 4.1.3, TS 1.32.2)

- Orchestrator as one Streamable-HTTP MCP server: `list_departments`, `delegate(department, task, tier,
  wait_seconds)` → job handle, `get_job`, `cancel_job`, `record_lesson`; Bearer token env var NOT matching
  `*_API_KEY`/`*_TOKEN` patterns Claude Code redacts (e.g. `ORCHESTRATOR_SECRET`... check redaction list).
- Per-department least-privilege toolsets (filesystem rw/ro mounts, git, serena, context7, playwright, github
